# Регламент двух писателей: slider-qa-docs и slider-autotests

Дата: 2026-10-01. Стороны: **первый писатель** — `slider-web-control-plane`; **второй писатель** —
`ausn-control-plane` (профиль `slider`). До введения регламента второй писатель не был известен первому.

Цель общая: повышение качества Slider AI. Репозитории `slider-qa-docs` (принятая командная QA-база) и
`slider-autotests` (исполняемое покрытие) — **разделяемые**: их ведут оба писателя.

## Правила записи в разделяемые репозитории

1. Перед правкой — `git pull --ff-only`; локальные расхождения не сбрасывать.
2. Изменения — **отдельной веткой и merge request**. Прямой push в `main` допустим только по явному
   согласованию между писателями (мелкие однострочные правки/опечатки).
3. **Force-push запрещён.** Чужие коммиты и ветки не перезаписывать и не удалять.
4. Конфликт или расхождение контракта — остановиться и согласовать; не «дописывать за другого».
5. Номера задач — только в provenance/`source`, а не в именах документов, кейсов и наборов.

## Зоны ответственности

| Область | Владелец |
|---|---|
| Правила, промпты, agent-layer, инфраструктура управления | первый писатель (`slider-web-control-plane`) |
| Исполняемое покрытие (`slider-autotests`): тесты, fixtures, прогоны | оба; изменения через MR |
| Принятая база (`slider-qa-docs`): разделы, чек-листы, кейсы, трассируемость | оба; изменения через MR |
| Продуктовые репозитории (`slider-web-editor`, `slider-ai-dashboard-frontend`, `slider-ai-frontend-landing`, `flask-slider-webeditor`, `pptx-converter-service`, `web_search_yandex`) | **только чтение**: ветки/worktree/файлы не создавать |

Task-ветки и worktree допустимы **только в `slider-autotests`**. Merge в `stage` выполняет пользователь.

## Артефакты и проверки

- Временные отчёты/доказательства — только в ignored `.reports/`; после переноса результата task-отчёты
  удаляются (Git хранит историю).
- Перед коммитом содержательных правок — регенерация trio `docs/codemap/codemap.{html,json,lock}`;
  генератор карт — **наш** (`ausn-control-plane/tools/codemap`), командой из соответствующего репозитория.
- Документы QA-базы обязаны иметь `freshness_status`, `source`, `last_verified`, `acceptance_gate` и связь
  с областью/автотестом/объяснённым manual gap; current меняется только после ACCEPTED.
- MCP-находка не считается покрытием, пока не преобразована в pytest/Playwright-тест, manual-only сценарий
  или blocked-by-testability запись.

## Секреты

Секреты — только в локальном `.env` соответствующего контура; в Git не попадают, в переписку не выносятся.

## Взаимодействие

- Уведомления и обсуждения — через merge requests и комментарии в GitLab.
- Спорные технические решения — по единой цели (качество Slider AI); при недостижении согласия вопрос
  эскалируется пользователю.
