# Дополнение независимой QA-рецензии

Перед полной регрессией нужно дополнительно подтвердить:

- ожидаемый и фактический BOM каждого стенда: сервис, commit/image digest, конфигурация и версия миграции схемы;
- authoritative acceptance criteria и владельца спорных правил для релиза;
- доступность Keycloak, DSS, PostgreSQL и тестового контура ФНС сквозным smoke, а не только инфраструктурными пробами;
- допустимое время сходимости асинхронных процессов, retry/DLQ и идемпотентность;
- безопасные синтетические субъекты, разрешённые изменяющие операции и порядок очистки.

Пять открытых High/Highest не равны пяти блокерам: для каждой задачи нужны fixVersion, затронутая сборка, воспроизводимость и решение по риску. Аналогично, failed frontend pipeline не доказывает дефект развёрнутого UI, а 34 Ruff violations не доказывают функциональную недостоверность тестов — оба сигнала требуют классификации.
