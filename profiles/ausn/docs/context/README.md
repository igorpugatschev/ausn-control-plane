# Контекст ПК АУСН перед тестированием

Актуальность снимка: **2026-09-08**.

Этот каталог содержит переносимый, проверяемый контекст для начала QA-работы с ПК АУСН. Он не является постоянной истиной: оперативные данные стендов, веток, задач и логов меняются. Перед новой тестовой сессией сначала сверяйте [реестр источников](evidence-register.md) и обновляйте только изменившиеся наблюдения.

## Состав

- [Карта системы](system-map.md) — назначение, компоненты, данные и ключевые потоки.
- [Текущее состояние](current-state.md) — подтверждённый снимок репозиториев, стендов, наблюдаемости и работ.
- [QA-вход](qa-entry-context.md) — риски, неизвестные и порядок разведки перед непосредственными проверками.
- [Реестр источников](evidence-register.md) — происхождение фактов, свежесть и ограничения доказательств.

## Правила использования

1. Отделяйте факт от вывода и предположения.
2. Не считайте `container Up`, HTTP 200, доступную БД или Prometheus `up=1` доказательством корректности бизнес-процесса.
3. Не сохраняйте сюда токены, пароли, персональные данные, ИНН, содержимое закрытых логов и дампы БД.
4. Источники разработки используются только для чтения. QA-артефакты создаются в `ausn-control-plane`.
5. Для исследования стендов используйте skill `qa-mcp`, для тест-дизайна — `qa-methodology`.

## Краткий итог снимка

Инфраструктура test1/test2 технически доступна, основные сервисы запущены, базы читаются, метрики и логи поступают. При этом готовность к системному тестированию пока **условная**: test2 содержит смешение релизных веток, один из основных frontend-pipeline недавно падал, pipeline QA-проекта не проходит quality gate, а в активной разработке находятся несколько сквозных и миграционных изменений. До широкой регрессии нужно подтвердить точный состав релиза и выполнить узкий smoke критических цепочек.
