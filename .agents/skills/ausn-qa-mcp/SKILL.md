# QA АУСН через MCP

## Выбор инструмента

| Задача | Сервер | Начать с |
|---|---|---|
| Требования, критерии приёмки, статус задачи | atlassian | jira_get_issue, confluence_get_page, confluence_search |
| Код, MR, версия на стенде, CI | gitlab | get_project, get_merge_request_diffs, list_deployments, list_pipelines |
| Решения команды, история обсуждений | mattermost | search_posts, read_post |
| Семантический поиск и влияние изменений | socraticode | codebase_status, codebase_search, codebase_impact |
| Состояние данных | test_pgdb | list, затем query |
| Логи и причины ошибки | test_graylog | get_current_time, list_streams, search_messages |
| Метрики и здоровье сервисов | test_grafana | list_datasources, query_prometheus, check_datasources_health |
| Процессы, контейнеры, конфигурация стенда | test_ssh | list_servers, generate_session_id, execute |
| Воспроизведение UI, сеть, консоль | playwright | browser_tabs, browser_navigate, browser_snapshot |

Полный список: [catalog.md](references/catalog.md). Точные параметры: соответствующий
`references/<server>.json` из ссылок каталога. Прочитать только выбранные контракты,
не загружать весь каталог JSON в контекст. Имена вида `mcp__<server>__<tool>` — адаптер
клиента; сам MCP объявляет короткое имя инструмента. При расхождении использовать живую схему.

## Рабочий подход

1. Определить цель проверки, стенд, версию/ветку и ожидаемое поведение. Использовать уже известный контекст.
2. Выбрать минимальный набор инструментов; начинать с идентификаторов/метаданных,
   затем ограниченного запроса, а не полного дампа данных.
3. Для дефекта сопоставить требование, фактический UI/API-результат, время UTC и
   подтверждение в логах/БД/метриках. Гипотезы отделять от наблюдений.
4. Артефакты сохранять в control plane, используя относительные пути.
   Секреты, cookie, Authorization и персональные данные исключать из передаваемых доказательств.
5. Повторять проверку после исправления или нового факта; не считать tools/list проверкой бизнес-функций.

Практические последовательности и ограничения: [workflows.md](references/workflows.md).
Инфраструктура и источники: [project-context.md](references/project-context.md).

## Границы действий

- Мы QA: собственные правки исходников разработчиков запрещены. Разрешены fetch/pull --ff-only
  чистой рабочей копии; не сбрасывать локальные изменения и не переключать ветку без связи с задачей.
- Запрос на диагностику не разрешает execute DML/DDL, деплой, перезапуск сервисов,
  merge, push, удаление ресурсов или управление токенами. Такие действия требуют соответствующей задачи.
- Сообщения, комментарии, создание дефектов и изменение Jira выполнять только если пользователь поручил публикацию.
- SQL `query` предназначен для SELECT, `execute` — для DML/DDL. Даже SELECT с функциями
  может иметь побочные эффекты: использовать известные таблицы и безопасные выражения.
- SSH execute, UI-клики и browser_evaluate оцениваются по содержимому действия.
  browser_run_code_unsafe выполняет произвольный код на сервере, не является обычным средством чтения страницы.
- Не вызывать list_access_tokens для проверки доступности: он возвращает значения токенов.
- readOnlyHint/destructiveHint — подсказки сервера, а не гарантия безопасности или наличия прав.

## Подключение и актуальность

Настройки находятся в `.codex/config.toml`, `.vscode/mcp.json`, `.mcp.json` от корня проекта;
локальная авторизация — в `.env`. Инструкция запуска: `docs/mcp.md` от корня проекта.
Для Python использовать только проектную `.venv` (Python 3.12).

Каталог — снимок 2026-09-08, 397 инструментов девяти серверов после раскрытия категорий GitLab.
Для обновления подключиться по проектным настройкам, получить initialize/serverInfo/capabilities,
обойти все страницы tools/list, у GitLab раскрыть категории через discover_tools в отдельной сессии,
и заменить JSON-каталоги и индекс согласованно. Не запускать инструменты изменения ради инвентаризации.
Capabilities resources/prompts означают поддержку протокола; содержимое ресурсов и шаблонов этим снимком не собрано.

Если сервер не загрузился: отдельно проверить TCP, HTTP initialize и tools/list через настроенный
mcp-remote. Таймаут при открытом TCP-порте не доказывает проблему VPN или неверный токен.
Не включать debug с заголовками авторизации. После восстановления связи может потребоваться
перезапуск MCP-клиента для загрузки отсутствующих инструментов.
