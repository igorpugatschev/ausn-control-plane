# Практические сценарии

## Требование → проверка → дефект

Получить Jira issue и связанные страницы Confluence через atlassian. Зафиксировать критерии приёмки.
Через GitLab установить релевантный MR, commit и deployment; успешный pipeline сам по себе не доказывает
развёртывание на выбранном стенде. Воспроизвести сценарий на согласованных тестовых данных.
Собрать шаги, ожидаемый/фактический результат, стенд, версию, время UTC и ссылки на доказательства.
Публикация в Jira или Mattermost — отдельное разрешённое действие, не обязательная часть диагностики.

## GitLab

Чтение: get_file_contents, get_repository_tree, get_commit_diff, get_merge_request_diffs,
list_merge_request_changed_files, list_pipeline_jobs, get_pipeline_job_output, list_deployments.
Использовать серверные фильтры и пагинацию по схеме инструмента. Логи CI могут содержать секреты.
При отсутствии нужного инструмента вызвать discover_tools без аргументов, затем с нужной category.
Категории issues, wiki, releases, tags, milestones и другие могут отсутствовать при старте.
Раскрытие категории меняет набор инструментов сессии, но не редактирует GitLab-проект.
Право видеть merge/create/delete не означает право или необходимость выполнять их.

## Mattermost

Для конкретного термина search_posts с короткими 1–2 ключевыми словами: keyword-поиск требует
совпадения каждого слова. Для смыслового поиска использовать естественный вопрос.
Упоминания людей искать по username, не смешивая его с ФИО. После поиска прочитать тред
через read_post или контекст канала через read_channel. Различать факт сообщения и актуальное решение.
Перед разрешённым create_post обязательно get_channel_info, проверить ID/команду/назначение канала.

## PostgreSQL

Сначала list: параметр server — имя конфигурации MCP, а не придуманное имя БД или IP.
Начальная проверка: query с {"server":"<из list>","sql":"SELECT current_database(), current_timestamp"}.
Затем исследовать нужную схему через information_schema и точечные SELECT с LIMIT.
Не делать SELECT * по крупным таблицам и не выгружать персональные данные без необходимости.
Для подготовки тестовых данных через execute нужны конкретная задача, точные записи и план очистки;
не предполагать, что транзакция сохраняется между разными MCP-вызовами.

## SSH

Получить имена подключений через list_servers. Один раз получить generate_session_id и
использовать этот ID во всех execute текущей беседы. В execute обязательны name, command,
sessionId и reasoningAndExpectations; явно описать цель, побочные эффекты и ожидаемый результат.
Начинать с ограниченных диагностических команд статуса/процессов/контейнеров.
Не выполнять общий дамп env, конфигураций с паролями или журналов без фильтра.
Команды используют окружение удалённой VM; локальная PowerShell-синтаксическая форма там неприменима.
Управление подключениями и access token не входит в обычную проверку стенда.

## Graylog

Получить get_current_time и list_streams; выбрать актуальный AUSN stream. При необходимости list_fields
с фильтром streams. Указать fields, иначе по умолчанию возвращаются лишь source и timestamp.
Начальный запрос (ID стрима подставить из list_streams):

```json
{
  "streams": ["<AUSN stream ID>"],
  "query": "application_name:core-dev AND Exception",
  "fields": ["timestamp", "application_name", "message", "full_message"],
  "range_seconds": 3600,
  "limit": 20,
  "offset": 0
}
```

Текущий сервер требует передавать время через range_seconds, а не timestamp внутри Lucene query.
Для исторического инцидента выбрать lookback, охватывающий событие, и учесть конечное окно при анализе;
не заявлять поддержку отсутствующих абсолютных start/end параметров. Избегать глубокой пагинации.
Для сводок aggregate_messages: groupings и metrics — массивы; например metrics=[{"function":"count"}].
Корпоративная памятка в ausn-ai содержит старые примеры timestamp-query: использовать её названия сервисов
как отправную точку, но синтаксис брать из текущего JSON-контракта.

## Grafana

list_datasources → get_datasource/health → метаданные метрик → ограниченный query_prometheus.
Не выдумывать datasource UID или label: получить list_prometheus_metric_names/label_names/label_values.
Для известного dashboard использовать get_dashboard_summary и get_dashboard_panel_queries,
а не сразу полный dashboard JSON. Привязать метрики к тому же стенду и временному окну, что логи.
grafana_api_request текущего сервера разрешает только GET; это средство чтения нестандартного endpoint.

## Playwright

Сначала browser_tabs и browser_snapshot: удалённая сессия может уже содержать нужную страницу.
После перехода использовать свежие refs снимка; не переиспользовать refs после существенного изменения DOM.
Проверять результат через browser_verify_* и фактическое состояние страницы, а не только успешный click.
Сеть: browser_network_requests → browser_network_request с index из списка (нумерация с 1).
Запрашивать нужную part; заголовки и body могут содержать токены и персональные данные.
browser_console_messages помогает сопоставить UI-ошибку с ответом API.
browser_route/network_state_set/storage/cookie changes меняют сессию: применять по сценарию,
фиксировать изменённое состояние и восстанавливать его после проверки.
Remote filename — путь на сервере Playwright, не на локальном ПК. Не считать его локальным артефактом
до фактического получения содержимого. Предпочитать вывод в ответ и сохранение в control plane;
запись на сервере вне указанных пользователем папок требует согласованного места назначения.

## SocratiCode

Перед поиском codebase_status; различать индексы control plane и ausn-ai. projectPath всегда относится
к нужному проекту, разрешённому из относительного расположения на текущей машине.
codebase_search для поиска по смыслу; graph_query для импортов, impact для потенциально затронутых
участков, flow для потока вызовов, symbols/symbol для символов. Граф — статический анализ, не runtime trace.
Нулевой граф документационного репозитория не означает, что текстовый индекс пуст.
После обновления источников codebase_update; поиск по старому индексу не заменяет проверку commit.
Удаление индекса и управление watcher — локальные изменения состояния, выполнять только по необходимости задачи.
