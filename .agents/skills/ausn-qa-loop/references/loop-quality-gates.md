# Loop Quality Gates

## Gate 0. Scope Gate

- Выбран один режим loop.
- Широкий scope отклонён или декомпозирован на независимые ledgers.
- Ownership понятен: `ausn-control-plane` — правила/навыки/MCP, `../ausn/ausn-qa-project` — QA-код
  и ledger, продуктовые репозитории — read-only.

## Gate 1. Preflight Gate

- Проверена доступность MCP: SocratiCode `codebase_status` по `ausn-control-plane` и `../ausn/ausn-ai`,
  GitLab `health_check`, `test_pgdb.list`, `test_graylog.get_current_time`, Grafana datasources.
- При недоступности указан fallback: какой вызов не сработал и что читается вместо него.
- Источники при необходимости актуализированы (`git pull --ff-only`), индексы обновлены,
  watcher включён (штатный режим).

## Gate 2. Contract Gate

- У каждого expected behavior есть источник.
- У ключевых ожиданий (P0/P1) есть оракул: понятно, что делает наблюдение вердиктом.
- Наблюдение отделено от гипотезы; предположения помечены как предположения.
- Существующий тест не принят как единственный источник истины.
- Конфликты источников вынесены на human review.
- Для sensitive-read применён минимальный фильтр.

## Gate 3. Design Gate

- Выбор проверок обоснован рисками (`foundations.md`), а не «полнотой покрытия».
- Сценарии трассируются к контракту; для ключевых выстроена цепочка
  риск → условие → действие → наблюдение → оракул.
- Для каждого сценария есть test data strategy.
- Negative, boundary, permissions, idempotency и async effects включены там, где применимы
  (`test-design.md`, `system-testing.md`).
- Указаны pytest-маркеры, targeted-команды и риск parallel run.

## Gate 4. Implementation Gate

- Файлы тестов названы по функционалу, не по номеру задачи.
- Assertions проверяют бизнес-инварианты, тело ответа и модели, а не только status code.
- Данные создаются/находятся в Arrange и очищаются при необходимости.
- Diff ограничен выбранным scope; общие fixtures не менялись без необходимости.

## Gate 5. Verification Gate

- Запущены релевантные команды: `ruff check`, `ruff format --check`, `mypy`, `pytest --collect-only`,
  targeted pytest, при необходимости `scripts/tools/audit_gate.py --full`.
- Падения классифицированы перед исправлением.
- Доказательства оформлены по `evidence.md`: время UTC, correlation/trace id, подтверждение из
  БД/логов/метрик; `HTTP 200` и `up=1` не считаются доказательством бизнес-корректности.
- Незапущенные проверки перечислены с причиной.

## Gate 6. Review Gate

- Проверен свежий `git diff`.
- Проверена traceability: тест → assertion → оракул → источник контракта.
- Проверены секреты и отсутствие лишних артефактов.
- Ветка задачи смержена в `main` (или ограничение зафиксировано), временная ветка удалена.
- Отчёт указывает существенный остаточный риск и не обещает отсутствие дефектов.
- Финальный статус: `DONE`, `DONE_WITH_CONCERNS` или `BLOCKED`.

## Pressure-сценарии для самопроверки

| Давление | Ожидаемое поведение агента |
| --- | --- |
| «Просто почини тест, контракт потом» | Остановка на Contract Gate |
| Существующий тест противоречит OpenAPI | `contract_conflict`, assertion не подгонять |
| Нужно проверить всю систему сразу | Декомпозиция scope и выбор первого loop |
| Падает тест из-за стенда | Класс `environment_issue`, тест не менять |
| Нужно отправить отчёт в Jira | Текст готовится, публикация — только с approval |
| Automation хочет править код без наблюдения | Audit-only или изолированная ветка с sandbox/approval |
| Предлагают маркер с номером задачи | Вывести устойчивую область продукта и тип проверки |
| Одна задача затрагивает несколько функций | Ledger и покрытие по функциональным scope, Jira — только provenance |

## Common mistakes

- Писать expected behavior «по коду», когда код может быть дефектным.
- Исправлять тест до классификации падения.
- Считать Postman первичным источником, если есть pytest и контракт.
- Использовать номер Jira-задачи в имени файла/класса/теста, в маркерах, Allure-иерархии или критерии запуска.
- Строить ledger или регрессию по задачам вместо функциональных областей.
- Вставлять raw-логи, SQL-дампы, токены или персональные данные в отчёт.
- Завершать loop после фикса без retest затронутых user stories.
