# Git Flow QA-проекта и control plane

## Назначение

Порядок движения изменений: ветка задачи → проверки → commit → push → merge в `main` → удаление
ветки. Push выполняется сразу после commit: незапушенные правки теряются при потере рабочей копии.
Отдельно — правила для управляющего и продуктовых репозиториев.

## QA-проект `../ausn/ausn-qa-project`

1. Работать в отдельной ветке от актуального `main` (`main` — основная ветка репозитория, CI запускается на неё).
2. Перед изменениями проверить `git status`; не откатывать и не переносить чужие правки.
3. Реализовать изменения, выполнить релевантные проверки и self-review.
4. Commit и push — только после успешных проверок; сообщение описывает функционал,
   а не номер задачи.
5. Обновить `main` через `git pull --ff-only`; merge ветки задачи — после выполнения всех задач,
   проверок и приёмки.
6. Запустить релевантные проверки после merge, затем удалить ветку задачи.
7. Push выполняется сразу после commit: незапушенные правки теряются при потере рабочей копии.

Ранее (в прежнем управляющем проекте) использовалась модель `develop → main` с обязательным worktree.
В текущем репозитории основная ветка — `main`; worktree применяется только по явному запросу
пользователя или при параллельной работе над несколькими задачами.

## Управляющий репозиторий `ausn-control-plane`

- Commit и push — сразу, по завершении логического шага.
- Изменения носят документационный характер (правила, навыки, MCP-конфигурация, отчёты).
- Секреты — только в корневом `.env`; в документацию и конфиги не попадают.

## Продуктовые репозитории ПК АУСН

- Только чтение: `git clone` и `git pull --ff-only` для актуализации источников.
- Никаких коммитов, правок, force-push и сбросов.

## Ограничения безопасности

- Не использовать `git reset --hard`, `git checkout -- .` и аналогичные команды без явной команды пользователя.
- Не делать force-push; не переписывать историю.
- Не удалять ветки и worktree с несохранёнными изменениями; при необходимости — stash с понятным именем.
- Перед merge проверить, что временные артефакты удалены или сохранены как утверждённая документация.
- Diff перед commit проверять на секреты, персональные данные и лишние файлы.
