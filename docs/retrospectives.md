## 2026-09-17 — подключение корпоративных MCP и выравнивание под шаблон ИИ-мета-репо

Контекст: перенос конфигурации корпоративных MCP из `.mcp.json` в `.opencode/opencode.jsonc` и приведение репозитория к шаблону ИИ-мета-репо (Confluence, pageId 195789365).

| # | Сценарий | Причина | Решение / профилактика |
|---|---|---|---|
| 1 | Серверы `type: "remote"` с `{env:VAR}` в заголовках не авторизуются | opencode не читает корневой `.env`; интерполяция разворачивается из пустого окружения | Серверы объявлять как `local` через `mcp-remote` из `tools/mcp-runtime` с `--env-file=.env` — тот же паттерн, что в `.mcp.json` |
| 2 | Токены вставлены в конфиг в открытом виде — нарушение правила «секреты только в `.env`» | Примеры на странице «Шаблон ИИ-мета-репо» подразумевают Bearer-токен прямо в конфиге | Не копировать паттерн `remote`+Bearer из шаблона; авторизация только через `.env`; в конфиге, уходящем в Git, секретов быть не должно |
| 3 | Висячие запятые в `opencode.jsonc` ломают старт opencode | opencode строго валидирует конфиг при загрузке и отказывается стартовать | Проверять синтаксис до сохранения; после правки перезапускать opencode и убеждаться, что конфиг загрузился |
| 4 | `instructions` ссылался на несуществующий `ENVIRONMENT.md` | Файл окружения не был создан на момент правки конфига | Целевой файл создавать до подключения ссылки; сейчас `ENVIRONMENT.md` существует и исключён из Git через `.gitignore` |
| 5 | Шаблон `rcktsci/projects/ai/meta-repo-template` недоступен по токенам (404) | Нет членства в приватной подгруппе `rcktsci/projects/ai` ни у Rocket.AI, ни у личного токена | Запросить доступ у владельца группы; до этого пользоваться реконструкцией с явной пометкой в `ENVIRONMENT-manual.md` |

## 2026-09-17 — восстановление quality gate ausn-qa-project (P1)

Контекст: CI на `main` не проходил минимум с 2026-07-28. Локальный gate был 11/11, но два пайплайна в CI упали на платформенно-специфичных проверках, невидимых с Windows.

| # | Сценарий | Причина | Решение / профилактика |
|---|---|---|---|
| 1 | Локально ruff чист, в CI 17× EXE001 «shebang without executable bit» | На Windows/NTFS все файлы «исполняемы» — локальный ruff слеп к git-режиму 100644; Linux-раннер видит его | Скриптам с shebang ставить `git update-index --chmod=+x`; помнить: локальные проверки на Windows не покрывают файловые режимы и Linux-специфику |
| 2 | В CI `pytest unit/static` упал с `FileNotFoundError: .reports/pytest-tmp-N` | pytest-basetemp не создаёт родителей; в CI каталога `.reports` нет, локально он существует — латентный баг вскрылся только когда validate-стадия впервые прошла | `mkdir -p .reports` в CI `before_script` + создание каталога в `audit_gate.py`; красная ранняя стадия маскирует падения поздних |
| 3 | Маркер `# audit: allow-mixed-status:` (с двоеточием) не отключает сканер mixed-status | Regex сканера `allow-mixed-status\s+\S` требует пробел после имени маркера | Сверять формат исключений с regex самого сканера, а не с примерами по памяти |
| 4 | Исходная причина сломанного gate — дрейф линтера без изменения кода | Плавающие версии (`ruff>=0.1.9`) + отсутствие lock: новые версии приносят новые правила (PLR0917) | Pin `ruff==0.16.6`, `mypy==2.3.1`; обновление инструментов — отдельный осознанный коммит с прогоном gate |

## 2026-09-17 — полный smoke test1/develop (этапы A–C)

Контекст: read-only и мутирующие smoke-наборы каркаса против test1; 8 находок, из них 2 продуктовых кандидата.

| # | Сценарий | Причина | Решение / профилактика |
|---|---|---|---|
| 1 | `httpx.ConnectTimeout` на 7 тестах выглядел как деградация стенда | В тесте захардкожен адрес прежнего контура `192.168.20.18:8001`; TCP-таймаут ≠ ошибка приложения | Проверять здоровье стенда (actuator, контейнеры без рестартов) и фактический адрес запроса; адреса брать из settings, а не хардкодить |
| 2 | `TOOLING_URL` отсутствовал в `.env` → тесты молча пошли на легаси `192.168.20.18:8080` | Пустое значение падает на дефолт `settings.py`, указывающий на прежний контур | Заполнять все URL в `.env`; отсутствие обязательной переменной должно падать явно, а не таймаутить |
| 3 | Массовые failed (32) вместо skipped в RBAC-наборе | Не были заданы `AUTH_TOKEN_BOUND_BANK_CLIENT`/`AUTH_TOKEN_EX_BANK_CLIENT` | Сначала проверять полноту `.env`; после заполнения тесты сами дают skipped с причиной (403 на `/taxpayer`) |
| 4 | 9 fixture-ошибок: `set admin_auth_client_secret` | Каркас требует client secret даже для публичного Keycloak-клиента (password grant без секрета даёт HTTP 200) | Дефект каркаса: добавить поддержку public-client password grant |
| 5 | `POST /api/v1/accrual/ens|oss` → 500 вместо 404/405 | Graylog: `handleNoResourceFoundException: No static resource ...` в front-module, `Error while processing request:` в gateway | Диагностика через Graylog: сопоставление UTC-времени с прогоном и маппинг source-контейнера по 12-символьному ID (`docker ps --no-trunc`) |

Дополнительно: Kafka на одном хосте использует разные порты (test1 — `9091`, test2 — `9092`) —
легко перепутать; проверять принадлежность порта стенду, а не только хосту.

## 2026-09-17 — подготовка данных для uc20/uc22 (шаг 3)

| # | Сценарий | Причина | Решение / профилактика |
|---|---|---|---|
| 1 | Гипотеза «зависшие PROCESSING блокируют новые заявки» не подтвердилась | Воспроизводящий POST создал заявку (HTTP 200), несмотря на 7 зависших строк | Проверять гипотезу воспроизведением до вывода; фиксировать в отчёте отвергнутые гипотезы отдельно |
| 2 | uc20/uc22 пропускаются, заявки массово падают в ERROR | Тест подаёт заявку с фиксированной датой в прошлом и общим ИНН → бизнес-отказ `UPDATE_TAX_OBJECT_ALREADY_DECLARED_ERROR`; каждый прогон добавляет ERROR-заявку | Уникальные данные на прогон (дата подачи/ИНН), а не подбор другого существующего ИНН |
| 3 | Диагностика состояния заявок | — | Быстрый путь: read-only SELECT в `test1-front-module.applications` (поля `request_status`, `response`) даёт бизнес-причину отказа без Graylog |
| 4 | Вторая отвергнутая гипотеза: «отмена разблокирует сразу» | Отмена сама идёт через очередь (CANCEL_* остаётся в PROCESSING), а заявки живут в PROCESSING ~28 минут | Не считать единичный удачный probe доказательством устойчивого поведения: проверять серию и состояние очереди; уборку делать best-effort, а скип-защиту оставлять |
| 5 | Путь `cancel_document` из документации даёт 404 | В живой контракте путь с дефисом: `cancel-document` (проверять по `/v3/api-docs`, а не по тест-кейсу) | Сверять пути OpenAPI перед реализацией; расхождение зафиксировать как дрейф документации |
