## 2026-09-17 — восстановление quality gate ausn-qa-project (P1)

Контекст: CI на `main` не проходил минимум с 2026-07-28. Локальный gate был 11/11, но два пайплайна в CI упали на платформенно-специфичных проверках, невидимых с Windows.

| # | Сценарий | Причина | Решение / профилактика |
|---|---|---|---|
| 1 | Локально ruff чист, в CI 17× EXE001 «shebang without executable bit» | На Windows/NTFS все файлы «исполняемы» — локальный ruff слеп к git-режиму 100644; Linux-раннер видит его | Скриптам с shebang ставить `git update-index --chmod=+x`; помнить: локальные проверки на Windows не покрывают файловые режимы и Linux-специфику |
| 2 | В CI `pytest unit/static` упал с `FileNotFoundError: .reports/pytest-tmp-N` | pytest-basetemp не создаёт родителей; в CI каталога `.reports` нет, локально он существует — латентный баг вскрылся только когда validate-стадия впервые прошла | `mkdir -p .reports` в CI `before_script` + создание каталога в `audit_gate.py`; красная ранняя стадия маскирует падения поздних |
| 3 | Маркер `# audit: allow-mixed-status:` (с двоеточием) не отключает сканер mixed-status | Regex сканера `allow-mixed-status\s+\S` требует пробел после имени маркера | Сверять формат исключений с regex самого сканера, а не с примерами по памяти |
| 4 | Исходная причина сломанного gate — дрейф линтера без изменения кода | Плавающие версии (`ruff>=0.1.9`) + отсутствие lock: новые версии приносят новые правила (PLR0917) | Pin `ruff==0.16.6`, `mypy==2.3.1`; обновление инструментов — отдельный осознанный коммит с прогоном gate |

| 51 | Файл `new_taxpayersItems.json` с токеном сгенерированного НП попал в коммит и был запушен | `.gitignore` обновлялся в том же вызове, что и `git add -A`; файл уже был в индексе после восстановления legacy-скрипта | Секретосодержащие пути добавлять в `.gitignore` **до** создания файлов; перед commit просматривать `git status --short` на неожиданные новые файлы; при инциденте — `git rm --cached` + решить вопрос истории (purge/ротация) с пользователем |
| 52 | Генератор НП отдавал 403 с рабочей машины | Эмулятор ФНС `usnonline.gnivc.ru:8443` пускает только адреса из белого списка; стенд ходит через офисный прокси `10.3.219.1:3128` | Запускать генерацию через прокси (`-x http://10.3.219.1:3128`) со стенда (MCP `test_ssh`); локальный прямой вызов не использовать |
| 53 | Токен эмулятора ФНС не подходит как `X-Client-Data` (фронт-модуль отдаёт 400) | `X-Client-Data` — PlainJWT с клеймами (inn/kpp/orgName), его формирует gateway; токен эмулятора относится к банковскому/ДБО-контуру | Не использовать токен эмулятора напрямую во фронт-модуле; для UI-тестов вводить ИНН в харнесс, сгенерированный НП нужен для приёма заявления в ФНС |
| 54 | PowerShell-обёртка портит кириллицу: stdout нативных команд обрезается, `Get-/Set-/Add-Content` перекодируют файлы (так испорчен `.gitignore`) | В PowerShell 5.1 вывод нативных процессов декодируется не в UTF-8, а командлеты читают и пишут в кодовой странице консоли | Текст создавать и править только инструментами `write`/`edit`/`read`; shell-обработку запускать через Git Bash (`& "C:\Program Files\Git\bin\bash.exe" -lc 'bash tmp/script.sh'`) со скриптом-файлом и записью результата в файл; кириллицу не передавать аргументом командной строки |
| 55 | Негативный UI-тест Keycloak (неверный пароль) упал: страница ошибки не найдена | Фиксированная пауза 3 с не гарантирует появление элемента ошибки в теме Keycloak | Не проверять асинхронный UI фиксированным `sleep`: `locator.wait_for(state="visible", timeout=...)` + проверка непустого текста ошибки; паузы оставлять только для «созревания» приложения после postMessage |
