# MCP проекта

Настройки без секретов:

- `.codex/config.toml` — Codex Desktop, CLI и расширение Codex в VS Code.
- `.vscode/mcp.json` — MCP-клиент VS Code.
- `.opencode/opencode.jsonc` — opencode; серверы запускаются как `local` через тот же `mcp-remote`, потому что remote-серверы opencode не читают `.env`.
- `.mcp.json` — другие совместимые клиенты.

Включены Atlassian, GitLab, Mattermost, SSH, PostgreSQL, Graylog, Grafana и Playwright
(SocratiCode — **по требованию**, см. `docs/socraticode.md`: сервер добавлен не в конфиги, а
включается на время задачи, чтобы не платить за ~25 инструментов в каждой сессии; решение 2026-09-29).
Telegram необязателен и не подключён. Источник истины — сами конфиги;
расхождения проверяет гейт `tools/checks/mcp_parity.py`.

Корпоративные MCP запускаются через локальный `mcp-remote` версии 0.8.4.
Node.js читает корневой `.env` через `--env-file`; вручную экспортировать переменные
перед запуском редактора не требуется. Запускайте Codex из корня проекта.
VS Code задаёт рабочий каталог через `${workspaceFolder}`.

После клонирования:

1. Установить Node.js 22+ и выполнить `npm ci --prefix tools/mcp-runtime`.
2. Получить локальный `.env` по разрешённому корпоративному каналу. Он не хранится в Git.
3. Для Сократа выполнить настройку из `docs/socraticode.md`.
4. Открыть проект и подтвердить доверие к проекту/MCP, если клиент запросит его.

Авторизация хранится в `.env` как полный заголовок:

- `MCP_GITLAB_AUTHORIZATION`: отдельный MCP Bearer-токен; `GITLAB_ACCESS_TOKEN` остаётся для репозитория.
- `MCP_MATTERMOST_AUTHORIZATION`: Bearer-токен Mattermost.
- `MCP_SSH_AUTHORIZATION`: Bearer-токен SSH MCP.
- `MCP_GRAYLOG_AUTHORIZATION`: рабочий Basic-заголовок Graylog.

Эти значения берутся из одобренной корпоративной конфигурации; путь к репозиторию
разработчиков во время запуска не нужен. Кэш авторизации остаётся в `.local/mcp-auth`.
Не включать отладочные журналы с заголовками авторизации.

После изменения настроек перезапустить Codex либо выполнить `Developer: Reload Window`
в VS Code. Автозапуск VS Code настроен через `chat.mcp.autostart`; первичное доверие
к серверам подтверждается пользователем. Подключение не означает разрешение изменять
корпоративные данные: действия выполняются только в рамках текущей QA-задачи.
