## `codexcli-ausn`

Исторический управляющий проект содержит полезные, в основном переносимые правила:

- Сократ как первый источник чтения проектов;
- contract-first анализ задачи;
- разделение источника требований, существующих тестов и coverage gaps;
- уникальные данные для параллельного выполнения;
- обязательная фильтрация Kafka по идентификаторам;
- Pydantic/schema validation вместо проверки только HTTP status;
- cleanup либо явная идемпотентность;
- классификация падения на product/test/environment/data/contract;
- evidence по API, topic, БД, логам и воспроизведению.

Устаревшими считать абсолютные пути, старые IP/порты, статические INN/UUID, старые auth fixtures и предположения о структуре сервисов. Старые планы и спецификации — исторический контекст, а не действующая инструкция.
