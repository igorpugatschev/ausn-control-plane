# Текущее состояние ПК АУСН

Дата наблюдений: **2026-09-08**. Все проверки были только для чтения.

## Доступность среды

- На `test1` и `test2` контейнеры основных backend, frontend, gateway и вспомогательных компонентов находятся в состоянии `Up`.
- Доступны чтению 10 PostgreSQL БД: по пять сервисных БД на test1 и test2 (`core`, `categorizer`, `front-module`, `dbo-integration`, `admin`). Выполнен только безопасный `SELECT` текущей БД и времени.
- Оба источника метрик Grafana/Prometheus отвечают успешно.
- В источнике `ausn-test` обнаружено 30 целей с `up=1`, включая основные backend и gateway-профили test1/test2.
- Graylog принимает значительный поток сообщений. За последние 24 часа встречались уровни `7`, `6`, `4`, `3`; прежняя проверка по `30000/40000` была неверна для фактической шкалы и не доказывала отсутствие ошибок.

Ограничение: эти признаки подтверждают доступность процессов, БД, scrape-endpoint и логирования, но не корректность сценариев и не готовность релиза.

## Текущая продуктовая нагрузка

В Jira проекта `PKAUSN` найдено 1950 задач. Срез последних изменений показывает активный релиз `1.11.0` и параллельную работу над:

- шаблонами и административным представлением НДФЛ;
- RBAC административной панели;
- мигратором данных `core → front-module`;
- API-first контрактами и генерацией;
- привязкой/отвязкой информационного партнёра и reconciliation последствий старого дефекта;
- правилами категоризатора и оптимизацией БД;
- банковскими интеграциями.

Открыто пять задач приоритета High/Highest в проверенном срезе. Среди них есть продуктовые дефекты/задачи по API, external-unbind reconciliation, миграции и документации. Количество само по себе не является критерием качества; важна их связь с тестируемым релизом.

## Операционные сигналы

В свежих обсуждениях команды обнаружены два анонимизированных сигнала, требующих воспроизводимой проверки:

1. Накопление порядка десятков тысяч старых/неприменимых операций в `categorized_buffer_operation` с периодической загрузкой батчей в память. Обсуждение предполагает, что фильтрация по периоду АУСН могла сработать не так, как ожидалось.
2. После регистрации с максимальными правами кабинет может показывать минимальные права, если последующий GET ФНС возвращает `DEFAULT`; сохранённого автоматического сравнения «запрошено → выдано» и дожима прав не подтверждено.

Это пока не формализованные дефекты: нужны очищенные тестовые данные, воспроизведение и корреляция по trace/message IDs.
