# Переносимость: единый источник и read-only bootstrap (инкремент 1) — дизайн

Статус: утверждён 2026-10-01. Основание — `OPENCODE_PORTABILITY_OPTIMIZATION_PROMPT.md`
(минимальная реализация Фаз 1–4) и решение о быстрых фиксах переносимости.

## Цель и границы

Цель — воспроизводимый путь **clone → окружение → MCP → проверка → первая задача** с машинной
проверкой готовности. В этом инкременте вводятся **канонические манифесты** и **read-only проверка**;
изменения в чужие системы и сетевые действия не выполняются.

**Вне рамок инкремента:** `--apply` (клонирование, `npm ci`, `docker compose up`), рентерация четырёх
клиентских конфигов из манифеста, автоматизация индексации/health-probe, clean-clone pilot, настройка
`ausn-qa-project` (отдельная задача QA), изменения корпоративного плагина.

## Компоненты и контракты

### 1. `configs/workspace.json` — реестр соседних репозиториев
Поля записи: `id` (уникальный), `path` (относительный от корня control plane, напр. `../ausn/ausn-core`),
`url` (HTTPS GitLab), `access` (`read-only` | `writable`), `required` (bool), `index` (нужна индексация
SocratiCode), `contextArtifacts` (bool), `defaultBranch`.

Правила: только относительные пути; `id`/`path` уникальны; нет одновременного `read-only` и `writable`
для одного пути; writable — только `ausn-qa-project`.

### 2. `configs/env.schema.json` — имена переменных
Записи: `name`, `group` (`mcp` | `gitlab` | `stands` | `ai`), `required` (bool), `source` (какой конфиг
использует). Хранятся и проверяются **только имена**; значения не читаются, не хранятся и не выводятся.

### 3. `configs/mcp/servers.json` — канонический манифест MCP
Записи: `name`, `type` (`local` | `remote`), `command`/`args` (для local), `env` (только имена),
`required` (bool), `clients` (`opencode` | `codex` | `vscode` | `mcp`), `healthProbe` (описание пробы).

Четыре клиентских файла (`.mcp.json`, `.vscode/mcp.json`, `.codex/config.toml`,
`.opencode/opencode.jsonc`) остаются, но проверяются **против манифеста** (semantic parity), а не только
друг против друга. Генерация клиентских конфигов из манифеста — отдельный инкремент (формы разные).

### 4. `scripts/bootstrap.mjs` — read-only проверка
Node ESM (22+), без зависимостей (как `.opencode/plugin/socraticode.js`). Режимы:

- `--plan` (по умолчанию) — что проверяется и что было бы создано/клонировано; ничего не меняет.
- `--check` — то же с фактическим вердиктом; код возврата `0` — всё обязательное зелёное, `1` — есть
  нарушения.

Проверки `--check`:

1. **workspace:** все `required: true` пути существуют; в манифесте нет абсолютных путей; нет конфликтов.
2. **env:** для каждого `required` имени — присутствие в `.env` (только имена); отсутствующие — typed gap
   с точной командой (скопировать из `.env.example`).
3. **mcp:** четыре файла семантически равны манифесту (name/type/command/args/имена env/required).
4. **infra (soft, не валит вердикт):** доступность Docker, `Qdrant /readyz`, `Ollama /api/tags`;
   индексы проектов — только если доступны MCP-инструменты, иначе typed gap «проверить в сессии».

Отчёт: человекочитаемо в stdout + redacted JSON-receipt в `.reports/bootstrap-<UTC>.json` (каталог
gitignored). Секреты и Authorization в отчёт не попадают.

### 5. Гейты и тесты
- `tools/checks/validate_manifests.py` — JSON-Schema-валидация трёх манифестов + negative-фикстуры:
  абсолютный путь, дубликат `id`, конфликт `access`, отсутствующее обязательное имя env, неизвестный
  `type` MCP.
- `tools/checks/mcp_parity.py` — дополнительно сверяет клиентские конфиги с `configs/mcp/servers.json`.
- secret-scan: проверка, что receipt/вывод не содержат значений секретов (только имена).

## Ошибки и коды

- `0` — обязательные проверки пройдены; `1` — есть нарушения; soft-предупреждения вердикт не меняют.
- Каждое нарушение — typed gap: что отсутствует и какой командой устранить.

## Риски

- **Спарка манифеста и четырёх файлов.** На этом инкременте — валидатор, не генерация (низкий риск).
- **Node-скрипт без зависимостей** совпадает со стилем плагина; совместимость с Windows проверяется тем
  же вызовом `node`.
- **Soft-проверки infra** не должны давать ложный «красный» на машине без Docker/VPN — они
  предупреждают, вердикт формируют обязательные проверки.

## Критерии готовности

1. `node scripts/bootstrap.mjs --check` зелёный на текущем окружении; красный — на негативных фикстурах.
2. `validate_manifests.py` и обновлённый `mcp_parity.py` проходят; negative-фикстуры падают ожидаемо.
3. `README.md` описывает одну команду проверки; `PROJECT_STATUS.md` отмечает Фазы 1–4 плана как частично
   выполненные (манифесты и read-only проверка).
4. `--apply` явно вынесен в следующий инкремент.
