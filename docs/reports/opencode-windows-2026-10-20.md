## Консольные окна

Исходная трассировка показала цепочку фонового сервера `opencode.exe → git.exe → conhost.exe`. Отдельные долговременные `cmd.exe` относятся к MCP-запускам через node/npx и не создавались заново на каждом обычном запросе. Само наличие conhost не доказывает видимость окна.

После обновления выполнено наблюдение за EVENT_OBJECT_SHOW для видимых ConsoleWindowClass и CASCADIA_HOSTING_WINDOW_CLASS без чтения заголовков и ввода. В заключительном интервале **21:05:01–21:05:51, Asia/Barnaul** зафиксировано **0 видимых консольных окон**. Внутри этого интервала, в 21:05:14, модель выполнила через Windows PowerShell ровно `git --version`; получены `git version 2.56.0.windows.2` и ответ SHELL_OK.

Экспериментальная подстановка windowsHide для Bun.spawn была проверена A/B: на 2.1.1 обе проверки показали 0 видимых окон, поэтому её польза не доказана. Обход и его временные файлы удалены. Бинарники Git/OpenCode не патчились; авторизация и MCP-конфигурация ради скрытия окон не менялись. Не утверждаем, что любой возможный сценарий интерфейса проверен.

## MCP и VPN

Подключены: context7, mattermost, test_graylog, socraticode, z.ai/zai; также обнаружен существующий slider_gitlab, его конфигурация в рамках этой проверки не менялась.

Atlassian, gitlab, test_ssh, test_pgdb, test_grafana и playwright завершали MCP-подключение с Request timed out. TCP-connect к их портам сам по себе не подтвердил доступность: общий TUN принимал даже соединение к порту 1, а HTTP к внутреннему адресу не отвечал. Windows Find-NetRoute показал маршрут через happ-xray вместо корпоративной VPN. Сравнительный HTTP-запрос из WSL тоже завершился тайм-аутом.

Существующий профиль RS office VPN был отключён; попытка подключения с сохранёнными Windows учётными данными завершилась RAS 628 (удалённая сторона разорвала соединение). Пароли не запрашивались и не выводились, маршруты и настройки VPN не менялись. Требуется успешное подключение корпоративной VPN владельцем; после этого нужно повторно подключить MCP в OpenCode и проверить их инструменты. Dozzle отдельно не слушает локальный порт 8081.

## Область ответственности и повторная проверка

Windows-часть выполнена в этом чате. Нативная WSL-установка, её отдельное хранилище, совпадение семи моделей и избранного переданы указанному пользователем WSL-чату. Windows и WSL не должны случайно выбирать один Windows npm-wrapper через PATH.

Повторная проверка Windows из корня проекта: `opencode --version`, `opencode plugin list`, `opencode models`, `opencode mcp list`. Секреты хранятся в штатном локальном хранилище OpenCode и в корневом .env; в отчёт не включались.

## Урок для ретроспективы

practice: различать запуск conhost и появление видимого окна; проверять интервал наблюдения по времени фактической shell-команды. Не оставлять глобальную подмену runtime API, если A/B-проверка не доказала её пользу. Предлагается перенести этот сценарий в docs/retrospectives.md.
